# Markdown-like Dialect — Minimal Grammar

This document defines a minimal, coherent Markdown-like grammar with
newline-significant prose, explicit escapes, and standard block syntax.

## Basic syntax

In the following syntax `\n` is meant to be interpreted as a new line contained in the cell (as plain markdown prevent line breaks in cells).

| Element | Encoding | Rendering | Rejected CommonMark feature | Comment |

## Tables

Tables follow standard Markdown rules with the following clarifications:

- Column separators use the `|` character.
- Header separator rows use dashes (`-`), but may be auto‑generated by the editor.
- Cell content is parsed inline according to this dialect.
- Literal `\\n` inside a cell represents a hard line break (`<br>`).
- Real newlines are not allowed inside table cells.
- No column alignment syntax (`:`) is supported.

## Properties

Object properties are represented between curly braces `{}`, the first word that appears in the curly braces is the name of the plugin / object, attributes take the form `variable=value` like in:

`{table width=1000px}`

Examples:

- `{heading numbered=true}` before a heading starts/marks numbering at that level.
- `{heading numbered=false}` before a heading disables numbering for that heading (useful to stop numbering below a certain depth).

## Escaping and forbidden syntax

### Backslash escaping

The backslash (`\\`) is the universal escape character.

- Outside of inline code and code blocks, a backslash escapes the next character.
- Inside inline code and code blocks, the backslash is rendered literally.

Defined escapes:

- `\\n` → hard line break (`<br>`)
- `\\ ` → non‑breakable space (U+00A0)

Any other sequence `\\x` renders as the literal character `x`.

### HTML

Raw HTML is **forbidden**.

- `<` and `>` are treated as plain characters.
- No HTML tags are recognised or rendered.

### Character entities

HTML character entities (`&...;`) are **not supported**.

- They are not recognised or interpreted.
- Authors should use UTF‑8 characters directly or backslash escapes instead.

## Special line break rules

### 1. Block parsing comes first

The document is first split into blocks using **standard Markdown block rules**:

- headings
- lists
- tables
- blockquotes
- code blocks
- top-level paragraphs

No newline reinterpretation happens at this stage.


### 2. Paragraphs are the only newline-sensitive blocks

Only **top-level paragraphs** reinterpret newlines.
All other blocks keep standard Markdown semantics.


### 3. Single newline in paragraph = hard line break

Inside a top-level paragraph:

```
line 1
line 2
```

renders as:

```html
<p>line 1<br>line 2</p>
```


### 4. Blank line = paragraph break

One or more blank lines terminate the current paragraph
and start a new one.


### 5. Trailing spaces have no meaning

Trailing whitespace is ignored everywhere.

The “two spaces = line break” rule does not exist.


### 6. Literal \n = explicit hard line break

The literal sequence `\n` produces a hard line break:

- valid anywhere (paragraphs, lists, tables)
- rendered as `<br>`


### 7. Structured blocks are unchanged

Inside:

- lists
- tables
- blockquotes
- code blocks

newlines keep their **standard structural meaning**.


### 8. Lists allow soft continuation

List items may span multiple lines per standard Markdown rules:

```
- item line one
  item line two
```

No special handling is applied.


### 9. Code blocks are opaque

Inside fenced or indented code blocks:

- no syntax is interpreted
- `\n` is literal
- newlines are preserved verbatim


### 10. Rendering is deterministic

Rendering rules:

- paragraph → `<p>`
- hard line break → `<br>`

Round-trip between raw, edit, and view modes must be lossless.

## Dialect Compliance Matrix

Status legend:
- `implemented`: behavior is present in current frontend pipeline.
- `partial`: behavior exists but with known gaps or ambiguity.
- `planned`: not implemented yet.

| Area | Rule | Status | Notes |
| -- | -- | -- | -- |
| Inline emphasis | `*italic*`, `**bold**`, `` `code` `` | `implemented` | Implemented via current mark handlers and printers. |
| Strike-through | `~~text~~` | `planned` | Not currently wired in core marks. |
| Underline | `_text_` means underline (not italic) | `planned` | Conflicts with CommonMark emphasis; requires explicit dialect parser/printer rules. |
| Headings | ATX headings (`#` .. `######`) | `implemented` | Setext headings are not implemented by custom handlers. |
| Lists (unordered) | `- item` | `implemented` | Core list handlers support this form. |
| Lists (ordered) | `1. item` (CommonMark) | `implemented` | Standard ordered-list syntax is canonical. Optional raw-mode helpers may auto-renumber without changing stored syntax. |
| Numbered headings | directive/property-based (`{heading numbered=true}`) | `planned` | Avoid a different syntax for numbered headers. Allows numbering to start below top-level title and be disabled at deeper levels with explicit properties. |
| Tables | Pipe table parse/print, directive support (`{table ...}`) | `implemented` | Parse + PM round-trip works with current table plugin. |
| Table line breaks | Literal `\\n` inside cell -> `<br>` | `partial` | `\\n` is converted to hard break in text pipeline; verify cell print strategy if multiline cells are required in output format. |
| Properties/directives | `{name key=value}` applied to next block | `implemented` | Strict directive parsing + plugin-owned mapping is active. |
| Raw HTML | forbidden | `implemented` | Markdown parser runs with `html: false`. |
| HTML entities | not interpreted specially | `partial` | Not explicitly transformed by custom logic; current behavior follows markdown-it defaults. |
| Line breaks in top-level paragraphs | single newline -> hard break | `implemented` | Implemented with context-aware `softbreak` handling. |
| Literal `\\n` escape | hard break in text contexts | `implemented` | Implemented in text token handler and serialized back from PM `hard_break`. |
| Two-spaces line break rule | disabled semantically | `partial` | Current behavior approximates target but remains dependent on markdown-it tokenization details. |
| Structured blocks newline semantics | unchanged for lists/tables/quotes/code | `implemented` | Softbreak re-interpretation is limited to top-level paragraphs. |
| Deterministic round-trip | raw <-> visual/view equivalence | `partial` | Core paths are stable; edge cases still exist for unsupported syntax and future dialect extensions. |
